# Лабораторная работа 2 — чтение информации из графических файлов

Приложение показывает для каждого файла: имя, формат, размер в пикселях, разрешение (dpi),
глубину цвета, сжатие и статус проверки. Форматы: JPEG, GIF, TIFF, BMP, PNG, PCX.

Можно открыть папку (вместе с подпапками) или выбрать отдельные файлы, убрать файлы из списка.
При клике на строку справа показываются превью, все характеристики с пояснениями и дополнительные данные.

## Запуск

```bash
./gradlew :lab2-image-info:run
./gradlew :lab2-image-info:test
```

Windows-установщик `ImageInfo.exe` собирает GitHub Actions (workflow **Build Windows EXE**).

## Как достаются данные

**Сторонние библиотеки для чтения метаданных не используются.** Файл открывается как
`FileChannel`, нужные байты читаются по смещениям из спецификации формата, числа собираются
вручную с нужным порядком байтов (`parser/BinaryFile`). JavaFX используется только для интерфейса
и показа превью.

### Определение формата (`FormatDetector`)

По сигнатуре в первых байтах файла, а не по расширению:

| Формат | Сигнатура |
|---|---|
| BMP | `42 4D` («BM») |
| PNG | `89 50 4E 47 0D 0A 1A 0A` |
| JPEG | `FF D8 FF` |
| GIF | «GIF87a» или «GIF89a» |
| TIFF | `49 49 2A 00` («II*») или `4D 4D 00 2A` («MM*») |
| PCX | `0A`, версия 0–5, кодирование 0/1, бит на пиксель 1/2/4/8 |

### Разбор форматов

| Формат | Класс | Порядок байтов | Откуда берутся данные |
|---|---|---|---|
| BMP | `BmpParser` | little-endian | BITMAPINFOHEADER: ширина — смещение 18, высота — 22, бит на пиксель — 28, сжатие — 30, пикселей на метр — 38, цветов в палитре — 46 |
| PNG | `PngParser` | big-endian | чанк IHDR: ширина — 16, высота — 20, бит на канал — 24, тип цвета — 25, чересстрочность — 28; далее проход по чанкам `[длина][тип][данные][CRC]`: PLTE — палитра, pHYs — dpi, IEND — конец |
| GIF | `GifParser` | little-endian | ширина — 6, высота — 8, байт 10: флаг и размер глобальной палитры 2^(N+1); далее проход по блокам 0x21 (расширения), 0x2C (кадры) до трейлера 0x3B |
| JPEG | `JpegParser` | big-endian | сегменты `FF xx [длина]` до SOS: SOFn — точность, высота, ширина, компоненты и их дискретизация; APP0 «JFIF» — dpi; APP1 «Exif» — камера, дата, разрешение |
| TIFF | `TiffParser` | II или MM | каталог IFD: записи по 12 байт `[тег][тип][количество][значение или смещение]`; теги 256/257 — размер, 258/277 — глубина, 259 — сжатие, 262 — цветовая модель, 282/296 — разрешение |
| PCX | `PcxParser` | little-endian | заголовок 128 байт: бит на пиксель — 3, Xmin/Ymin/Xmax/Ymax — 4…11, HDpi — 12, плоскостей — 65 |

Exif внутри JPEG — это мини-TIFF, он разбирается тем же кодом `TiffParser`.

### Вычисляемые значения

| Что | Формула |
|---|---|
| dpi из пикселей на метр (BMP, PNG) | × 0.0254 |
| dpi из точек на сантиметр (JPEG, TIFF) | × 2.54 |
| Глубина JPEG | точность × число компонент |
| Глубина PNG | бит на канал × число каналов (тип 2 → 3, 4 → 2, 6 → 4, иначе 1) |
| Глубина TIFF | сумма BitsPerSample по каналам |
| Глубина GIF | N + 1, где 2^(N+1) — размер палитры |
| Глубина PCX | бит на пиксель × число плоскостей |
| Размер PCX | Xmax − Xmin + 1, Ymax − Ymin + 1 |
| Субдискретизация JPEG | отношение коэффициентов H×V компоненты Y к Cb |

### Проверка файлов

| Статус | Когда |
|---|---|
| Не изображение | сигнатура не относится к шести форматам (например, текстовый файл с расширением `.jpg`) |
| Повреждён | заголовок не читается или файл обрезан: в PNG нет IEND, в JPEG нет SOF или маркера EOI `FF D9`, в GIF нет трейлера 0x3B, в BMP размер в заголовке больше файла, в PCX нет палитры в конце, полоса TIFF за концом файла |
| OK | всё прочитано |

Любое чтение за концом файла превращается в статус «Повреждён», программа не падает.

## Быстродействие

- Читаются только заголовки: первые 64 КБ файла и, при необходимости, небольшие окна по 16 КБ
  (хвост JPEG для EOI, следующий чанк PNG, каталог TIFF). Файл целиком в память не загружается.
- Файлы обрабатываются пулом потоков, их число выбирается в окне (по умолчанию 2 × число ядер).
- Интерфейс не блокируется: каждые 100 мс готовые результаты добавляются в таблицу и
  обновляется прогресс-бар.

300 JPEG 4000 × 3000 общим объёмом 1,9 ГБ обрабатываются за 0,14 с в 1 поток и за 0,06 с в 8 потоков
(файлы в кэше ОС).

## Структура

| Класс | Назначение |
|---|---|
| `Launcher` | точка входа |
| `MainApp` | окно, таблица, прогресс, многопоточный обход папки |
| `DetailsPane` | правая панель: превью, характеристики и пояснения |
| `ImageInfoReader` | определяет формат и вызывает нужный парсер |
| `ImageInfo` | результат по одному файлу |
| `parser/BinaryFile` | чтение байтов и чисел по смещению |
| `parser/FormatDetector` | определение формата по сигнатуре |
| `parser/*Parser` | разбор заголовков каждого формата |
